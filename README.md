# МТС | Инциденты в фокусе (Дашборд Координатора Массовых Инцидентов)

Монорепозиторий системы поддержки принятия решений и мониторинга инцидентов в реальном времени для отдела координации массовых инцидентов МТС 24/7.

## ⚡ Быстрый запуск

### 1. База данных PostgreSQL
База данных `itsm_dashboard` уже создана и настроена на локальном PostgreSQL (`localhost:5432`, логин/пароль: `postgres` / `postgres`).
Либо можно поднять через Docker:
```bash
docker compose up -d postgres
```

### 2. Запуск бэкенда (Go)
Из папки `backend`:
```bash
cd backend
go run ./cmd/server
```
При старте сервер автоматически:
* Создает таблицы в PostgreSQL
* Загружает начальные 44 инцидента из `data/character_problems.json`
* Запускает расчет скорингов ИИ (риск эскалации и маршрутизация)
* Поднимает HTTP API и стрим Server-Sent Events (SSE) на порту `8080`
* Автоматически раздает SPA фронтенд на `http://localhost:8080/`

### 3. Запуск фронтенда (React)
* **Готовый билд:** Уже встроен в бэкенд и доступен по адресу **[http://localhost:8080](http://localhost:8080)**.
* **В режиме разработки (Hot-Reload):**
  ```bash
  cd frontend
  npm run dev
  ```
  Фронтенд запустится на `http://localhost:3000` с автоматическим проксированием запросов к бэкенду.

## 🤖 Модели ИИ и ONNX

В проекте реализованы две ключевые функции ИИ:

### 1. Прогноз риска эскалации (Risk Assessment)
* **Файлы:** `backend/models_ai/risk_assessment.onnx` и `risk_assessment_model.json`.
* **Что делает:** Вычисляет процент риска $P(\text{critical}) \in [0, 100\%]$ срыва сроков SLA и эскалации инцидента в «Наивысший».
* **Учитываемые факторы:** `priorityId`, `urgencyId`, `impactId`, клиентский/технологический тип сервиса, ключевые риск-слова в тексте проблемы.

### 2. Подсказка по умной маршрутизации (Routing Hint)
* **Файлы:** `backend/models_ai/routing_hint.onnx` и `routing_hint_model.json`.
* **Что делает:** Классифицирует инцидент по тексту проблемы, названию продукта (`productName`), сценарию (`scenarioName`) и сервису, предлагая наиболее вероятную команду (`assignedGroupName`) из 22 команд с вероятностью уверенности (`confidence`).
* **Интерфейс:** В карточке инцидента координатор видит рекомендацию и кнопку **«Передать в 1 клик»**, которая сразу переназначает инцидент и рассылает апдейт по SSE.

### 3. Интеллектуальный прогноз риска срыва SLA (Predictive SLA & Team Workload)
* **Что делает:** Вычисляет риск срыва дедлайна с учетом:
  1. Текущей очереди незавершенных задач у целевой команды ($W_t$).
  2. Исторического профиля среднего времени решения (MTTR) для инфраструктуры, клиентских или сетевых сервисов.
  3. Множителя критичности и задержек в очереди (эффект очередей M/M/1).
* **Интерфейс:**
  - В карточке отображается: `Риск срыва SLA: X% (очередь: Y)`.
  - В тикер шапки вынесен счетчик `Риск SLA: N`.
  - В модальном окне выводится подробная раскладка: текущая очередь, расчетное время в часах и точный запас до дедлайна.

### 4. Трекинг предсказаний ИИ и обратная связь (`ai_predictions`)
* В отдельную таблицу PostgreSQL `ai_predictions` логируются все предсказания ИИ (рекомендация группы, уверенность, скоринг риска, вектор фичей).
* При действиях координатора (принятие подсказки или ручное переопределение) фиксируется факт `is_accepted: true/false`, что дает готовый размеченный датасет для непрерывного дообучения моделей (Online Feedback Loop).
* Подробнее в [docs/ai_predictions_tracking.md](docs/ai_predictions_tracking.md) и [docs/sla_prediction_model.md](docs/sla_prediction_model.md).

## 🎯 Сценарии для защиты (Live Demo на хакатоне)

В нижнем правом углу дашборда расположена интерактивная **Панель живой демонстрации**:
1. **«1. Критический сбой (KION)»**: Мгновенно генерирует аварийный инцидент наивысшего приоритета. Дашборд воспроизводит звуковой сигнал, выводит всплывающий алерт и помещает карточку в красную колонку с таймером SLA.
2. **«2. На координатора»**: Генерирует инцидент, назначенный на координаторов. Дашборд подсвечивает подсказку ИИ с рекомендованной командой и предлагает кнопку быстрой передачи.
3. **«3. Решить инцидент»**: Завершает критический сбой и переводит его в статус «Завершен», демонстрируя автоматическое обновление без перезагрузки страницы.
4. **«Сброс данных»**: Возвращает базу в исходное состояние файла `character_problems.json`.
