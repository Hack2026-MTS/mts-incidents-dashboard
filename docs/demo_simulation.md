# Демо-симуляция событий ITSM

Документ описывает устройство и механику работы модуля **живой демонстрации** (Live Demo), созданного для защиты кейса на хакатоне в соответствии с требованиями слайда 10:
> *«Живую демонстрацию: в файл с данными вносятся изменения, и дашборд на них реагирует. Как координатор узнаёт о критическом инциденте и его решении. Как координатор узнаёт об инциденте на координаторов. Как используется ИИ».*

---

## 1. Сквозная архитектура симуляции

Вся цепочка работает в реальном времени без перезагрузки страниц:

```
[UI: Кнопка демо / API curl]
            │
            ▼  POST /api/demo/...
┌───────────────────────────────────────────────┐
│              Go Backend Server                │
│ 1. DemoHandler формирует событие инцидента    │
│ 2. MLEngine на лету рассчитывает Risk & Route │
│ 3. DB сохраняет инцидент в PostgreSQL         │
│ 4. SSEHub отправляет событие в поток          │
└───────────────────────┬───────────────────────┘
                        │
                        ▼  Server-Sent Events (SSE)
┌───────────────────────────────────────────────┐
│                 React Client                  │
│ 1. sseService ловит сообщение                 │
│ 2. Web Audio API воспроизводит звук           │
│ 3. AlertToast показывает всплывающее окно     │
│ 4. Инцидент мгновенно встает в нужную колонку │
│ 5. Обновляется счетчик в шапке дашборда       │
└───────────────────────────────────────────────┘
```

---

## 2. Реализованные сценарии

### Сценарий 1: Критический сбой (`POST /api/demo/create-critical`)
* **Что происходит:** Симулируется внезапная массовая авария клиентского сервиса:
  * Продукт: *Онлайн-кинотеатр KION* (BI_KION_CORE)
  * Заголовок: *«МАССОВЫЙ СБОЙ: Отказ авторизации пользователей KION в МЦОД»*
  * Приоритет: `Наивысший` (`priorityId = 4`, `urgency = 4`, `impact = 4`)
  * Дедлайн: через 4 часа от текущего момента
* **Реакция ИИ:** 
  * `AIRiskScore`: **99%** (`CRITICAL`)
* **Реакция дашборда:**
  * Звучит тревожный двухтональный звуковой сигнал сирены.
  * Всплывает красный баннер тревоги.
  * Карточка падает в первую колонку **«Критические инциденты»** с красной пульсирующей рамкой и активным обратным таймером SLA.
  * Счетчик критических в шапке увеличивается на `+1`.

### Сценарий 2: Назначение на координатора (`POST /api/demo/assign-coordinator`)
* **Что происходит:** Симулируется инцидент инфраструктуры SAN/виртуализации, который ошибочно упал в общую очередь:
  * Группа: *«КЦ ИТ Координаторы Массовых Инцидентов»*
  * Заголовок: *«Ошибка репликации дисковых массивов SAN в кластере VMWare»*
* **Реакция ИИ:** 
  * Модель маршрутизации классифицирует проблему и вычисляет рекомендацию: команда **«КЦ ДОИ Администрирование SAN»** с точностью **97.8%**.
* **Реакция дашборда:**
  * Воспроизводится двойной мягкий звуковой сигнал (chime).
  * Карточка появляется во 2-й колонке **«На координаторах»**.
  * На карточке сразу горит подсказка: `💡 ИИ: КЦ ДОИ Администрирование SAN [97.8%]`.
  * Рядом доступна кнопка **«Передать»**, по нажатию на которую инцидент в один клик уходит целевой команде.

### Сценарий 3: Решение критического инцидента (`POST /api/demo/resolve-critical`)
* **Что происходит:** Активный критический инцидент переводится в статус:
  * `state = "Завершен"`, `stateEnum = "Completed"`, `completionDate = NOW()`
  * Заполняется поле `solution`: *«Проблема устранена: переключен резервный кластер шлюзов...»*
* **Реакция дашборда:**
  * Инцидент меняет визуальный стиль: красная рамка гаснет, появляется зеленый бейдж `✅ Решено`.
  * Счетчик критических в шапке сбрасывается обратно в 0.
  * Всплывает уведомление об успешном устранении аварии.

### Сценарий 4: Сброс базы (`POST /api/demo/reset`)
* **Что происходит:** Таблица `incidents` очищается и заново заполняется чистыми 44 инцидентами из исходного файла `data/character_problems.json`. Дашборд синхронно возвращается в исходное состояние.

## 3. Где находится код симуляции

1. **Бэкенд:** `backend/internal/api/demo.go` — логика формирования инцидентов и вызовы SSE-хаба.
2. **Роутер:** `backend/internal/api/router.go` — регистрация маршрутов `/api/demo/*`.
3. **Фронтенд компонент:** `frontend/src/components/DemoPanel.tsx` — плавающая кнопка `⚡ Демо-симуляция` в нижнем правом углу экрана.
4. **API клиент:** `frontend/src/services/api.ts` — функции `demoCreateCritical`, `demoAssignCoordinator`, `demoResolveCritical`, `demoResetData`.
5. **Аудио-генератор:** `frontend/src/utils/audio.ts` — генерация звуков тревоги и уведомлений через чистый Web Audio API (без внешних mp3-файлов).
